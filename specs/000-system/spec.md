# 000 시스템 전체

## 배경

작은 카메라가 영상을 Wi-Fi 로 바로 내보내는 일이 두 군데에서 문제가 된다.

- **몰카.** 숙소·화장실·탈의실에 숨겨 두고 영상을 실시간으로 내보내는 카메라. 필요한 근거는 [유용성 근거](../../research/유용성%20근거.md).
- **시험 부정행위.** 시험지를 찍어 밖으로 보내고 답을 받는 초소형 카메라. 받은 쪽에서는 사람이나 AI 가 문제를 푼다.

지금 파는 탐지기는 "근처에 전파가 있다"까지만 알려 준다. 어디에 있는지는 사람이 탐지기를 들고 구석구석 대 봐야 안다. 시험 중에는 감독관이 학생 사이를 돌며 그렇게 할 수 없다.

## 만드는 것

Wi-Fi 로 영상을 내보내는 카메라가 **있는지** 알아내고, **어디에 있는지**를 폰 화면에 겹쳐 보여 주는 시스템. 세 부분으로 나눈다.

| 부분 | 저장소 | 하는 일 |
|---|---|---|
| 수신기 | [receiver](https://github.com/DeteCam/receiver) | 둘레 Wi-Fi 를 엿들어 의심 기기를 고르고, 알루미늄 판을 돌려 그 기기의 방향을 재고, 여러 곳에서 잰 방향을 모아 위치를 낸다 |
| 앱 | [app](https://github.com/DeteCam/app) | 수신기를 조종하고, 결과(의심 구역, 자리 후보)를 카메라 화면 위에 띄운다 |
| 분석 | [ai](https://github.com/DeteCam/ai) | 의심 점수와 곡선 읽기를 데이터로 다듬는다. 다듬은 결과는 수신기에 넣는다 |

## 사용자 시나리오

1. **몰카 찾기.** 방에 들어가 수신기를 켜고 앱에서 '찾기'를 누른다. 약 30초 뒤 의심 기기 목록이 뜬다. 의심 기기가 있으면 수신기가 방향을 재고, 앱이 "저쪽으로 2m 옮겨 한 번 더"를 알려 준다. 두세 곳에서 재면 화면에 의심 구역이 뜬다.
2. **시험장.** 시험 전에 감독관이 수신기를 스탠드(높이 2.4m)에 올려 교실 벽 쪽에 세운다. 시험 중 의심 기기가 잡히면 앱이 다음에 옮길 곳을 알려 준다. 벽을 따라 여섯 곳쯤에서 재면 자리 후보 세 개가 확률과 함께 뜬다. 감독관은 그 자리를 눈으로 확인한다.

## 범위

| 카메라 | 다루는가 |
|---|---|
| 2.4·5GHz Wi-Fi 로 영상을 계속 내보내는 카메라 (공유기·폰 핫스팟에 붙었거나 스스로 AP 가 된 것) | **대상** |
| Wi-Fi 6 로만 붙는 카메라 | 탐지는 대상. 위치는 응답 신호(ACK)로 재는 방법이 실물로 확인되면 대상 |
| 버튼을 누를 때만 잠깐 보내는 카메라 | 범위 밖 (전파가 짧아 방향을 잴 시간이 없다) |
| 블루투스로 폰에 보내는 기기 (스마트 안경 등) | 범위 밖 |
| LTE·5G 로 직접 보내는 카메라 | 범위 밖 |
| 저장만 하는 카메라 (SD 카드) | 범위 밖 (전파가 없다) |

전파 방해(재밍)는 하지 않는다. 찾고 위치를 알려 주는 데까지만 한다.

## 요구사항

| 번호 | 내용 |
|---|---|
| SR-1 | 카메라가 어느 Wi-Fi 에 붙었는지 몰라도 찾는다 (숨긴 네트워크, 폰 핫스팟 포함) |
| SR-2 | 몰카와 시험장을 모드로 나누지 않는다. 단추 하나로 시작하고, 증거를 쌓은 '의심 점수'로 고른다 |
| SR-3 | 수신기는 노트북 없이 배터리로 혼자 동작하고, 폰으로 모든 동작을 시킨다 |
| SR-4 | 위치는 한 점이 아니라 구역(몰카)과 자리 후보 3개 + 확률(시험장)로 낸다 |
| SR-5 | 시험장에서는 수신기를 학생 사이로 들이지 않는다. 벽·모서리·교탁 쪽으로만 옮긴다 |
| SR-6 | 모든 부품은 테이프가 아니라 나사로 고정한다. 몸체는 3D 프린터로 뽑아 누구나 다시 만들 수 있다 |
| SR-7 | 결과 화면에 '확정이 아님'과 '찾지 못하는 카메라'를 밝힌다 |

## 성능 목표

숫자 옆의 근거가 '계산'인 것은 실물 실험으로 다시 확인한다.

| 번호 | 목표 | 확인 방법 | 지금 근거 |
|---|---|---|---|
| G-1 | 영상을 내보내는 카메라를 30초 안에 의심 기기로 올리는 비율 90% 이상 | 카메라 3종 × 장소 3곳 × 10회 | 계산 (의심 점수 검사 자료) |
| G-2 | 카메라가 아닌 기기를 의심 1순위로 올리는 비율 5% 이하 | 폰·노트북·TV 가 있는 방과 강의실에서 30회 | 계산 4~5% |
| G-3 | 가리는 것 없는 3m 에서 방향 오차 가운데값 15° 이하 | 0°·45°·90°·135° 각 3회 | 계산 4.5° (곡선 전체 맞추기) |
| G-4 | 방: 두세 곳에서 재어 반경 1m 구역 안에 카메라가 드는 비율 80% 이상 | 숙소 모양 방 3곳 × 10회 | 계산 |
| G-5 | 40석 교실: 여섯 곳에서 재어 '그 자리 또는 바로 옆자리'를 맞히는 비율 85% 이상, 걸리는 시간 25분 이하 | 강의실에서 카메라 자리 20곳 | 계산 98% ([교실 전파 시뮬레이션](../../verification/교실%20전파%20시뮬레이션.md)) |
| G-6 | 보조배터리로 1시간 이상 이어서 동작 | 측정을 되풀이하며 전압 경고가 없는지 | 계산 (전류 1.8A 이하) |
| G-7 | AR 로 띄운 구역이 실제 자리에서 0.3m 안 (3m 거리) | 줄자로 잰 자리와 화면 비교 10회 | 미확인 |

## 수용 기준

- 실물 수신기 한 대와 앱으로 시나리오 1·2 를 처음부터 끝까지 시연한다.
- G-1 ~ G-5 를 실물로 재어 표로 낸다. 목표에 못 미친 항목은 숫자와 까닭을 그대로 적는다.

## 확인할 것

- ESP32 가 카메라의 응답 신호(ACK)에서 전파 값(CSI)을 내주는지. 안 되면 카메라가 스스로 내보내는 영상 신호만으로 잰다 (라즈베리파이, 지금 되는 방법).
- 교실 계산은 책상 위 카메라 기준이다. 몸에 붙인 카메라(가슴, 안경)는 몸에 가려 더 어렵다.
- 기준 곡선(카메라 방향마다 판을 돌렸을 때의 신호 곡선)을 실물로 재서 계산값과 견준다.
